# Checklist

## 数据层

- [x] `Channel` 只读模型包含 `key`、`base_url`、`status` 字段，且不影响现有渠道查询接口
- [x] 渠道凭据查询按渠道聚合返回 base_url、key、status 与该渠道去重模型列表（`channels.key` 为保留字，SQL 别名用 `api_key` 规避 MySQL 1064）
- [x] `probe_settings`、`probe_runs`、`probe_results` 三张表在告警平台库自动建表成功（服务启动无迁移报错）
- [x] 探测配置持久化后可读回，服务重启不丢失（重启后日志显示恢复 `0 4 * * *` / `0 5 * * *`）
- [x] 探测结果（可用性 status_code/latency/error；质量 score/verdict/report_url）完整落库

## cron 与调度

- [x] 合法 5 字段 cron 表达式校验通过并返回下次运行时间（`*/15 2 * * 1-5` → 2026-09-21T02:00:00+08:00）
- [x] 非法 cron 表达式（字段数错误/语法错误）返回明确错误，且配置不被保存（回读仍为 `0 4 * * *`）
- [x] 配置保存后调度器无需重启即按新 cron 重排（热生效）
- [x] 同一探测任务不会重入并发执行（运行中再次触发返回 409）
- [x] 服务收到退出信号后调度器优雅停止（日志：`渠道探测调度器已停止` + `server stopped gracefully`）

## 可用性探测

- [x] 探测目标为「渠道白名单 ∩ status=1 ∩ 有 base_url+key」；白名单为空时覆盖全部满足条件的渠道
- [x] 每个目标渠道覆盖其全部模型（`max_models_per_channel`>0 时按上限截断）
- [x] 请求地址归一化正确：OpenAI 兼容模型 `base_url` 缺 `/v1` 时自动追加，最终指向 `/chat/completions`；Claude 系走 `/v1/messages`、Gemini 走 `/v1beta/models/{model}:generateContent`
- [x] 请求体为 `max_tokens=1`、`stream=false`、内容取自配置的 prompt（默认 `hi`）
- [x] `key` 为多值（逗号分隔）时使用第一个非空值
- [x] HTTP 2xx 记为成功并记录耗时；非 2xx 与网络错误/超时记为失败并记录状态码或错误原因（实测 200 → ok/1307ms；400 → fail/状态码落库）
- [x] 缺 base_url/key、非启用、不在白名单、无模型的渠道记为「跳过」，不纳入失败计数与告警
- [x] 在途探测请求数不超过配置的 `concurrency`（worker pool + 信号量）
- [x] 存在失败项时按渠道聚合发送一条飞书告警，含运行时间、失败渠道数、失败模型数与明细样本
- [x] 未配置 webhook 时仅记录日志与落库，探测任务本身不受影响（日志：`可用性探测存在失败项，但未配置飞书 webhook，仅记录日志`）
- [x] 冷却期内不重复发送告警；全部成功时不发送任何告警
- [x] 「立即执行」可手动触发一次探测，接口立即返回已受理（`{"accepted": true}`）

## 质量探测

- [x] 质量探测使用独立 cron，且不阻塞/不依赖本次可用性探测是否刚结束
- [x] 候选取自最近一次可用性运行的成功结果，按渠道分组、每个可用渠道随机抽 1 个模型
- [x] 无可用性成功结果时本次运行记为跳过并说明原因，且不发送告警（运行 #6：`没有可用的可用性探测成功结果，本次质量探测已跳过`）
- [x] 协议推断正确（claude→anthropic、gpt/o1/o3/o4/chatgpt→openai、gemini→gemini），无法推断的候选被跳过
- [x] 正确调用 veridrop 提交任务、轮询状态、拉取报告 JSON 并解析 `total_score`/`verdict`（实测命中 `/api/detect/claude`，落库 score=88.5、verdict=genuine）
- [x] 轮询总耗时受 `timeout_sec` 限制，超时记为失败并记录原因
- [x] 分数低于 `score_threshold` 或检测失败时发送飞书告警（含渠道、模型、分数、结论、报告链接）
- [x] 质量告警遵循 `cooldown_sec` 冷却
- [x] 「立即执行」可手动触发一次质量探测

## API

- [x] 探测配置读写接口返回配置 + 下次运行时间 + 调度状态（含最近一次运行的成功/失败/跳过统计）
- [x] cron 校验接口对合法/非法表达式返回正确结果
- [x] 运行历史接口按 kind（可用性/质量）返回触发方式、起止时间、总数/成功/失败/跳过
- [x] 结果明细接口支持按 run 查询与「仅看失败」筛选
- [x] webhook 连通性测试接口可发送测试卡片并返回结果（空地址 400；不可达地址返回 success=false + 错误原因）
- [x] 所有探测接口在 `/api/v1` 鉴权分组内，未带 token 访问返回 401

## 前端

- [x] 侧边栏新增「渠道探测」入口，点击切换到渠道探测页面
- [x] 页面可用性/质量两个页签均可编辑并保存配置，保存成功后再刷新能看到新配置
- [x] cron 输入非法时页面给出提示且不提交保存（点「保存配置」不发出 PUT 请求，仅显示行内红字与错误提示条）
- [x] 页面展示下次预计运行时间与上次运行摘要（上次运行时间、本次状态、上次运行结果 #N 总/成功/失败/跳过）
- [x] 页面可查看运行历史与失败明细（渠道、模型、状态码/错误原因、耗时；质量含分数与结论）
- [x] 页面可手动触发可用性与质量探测
- [x] 页面样式与现有控制台一致（含暗色主题下颜色与图标正常）
